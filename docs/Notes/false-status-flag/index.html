What a "false" status flag on the bench capture actually meant

November 10, 2026 · ARC, CBU1 VEX U Robotics

Note

The ARC RS-485 parser reads one byte at a time through a state machine instead of waiting for a whole buffer. A packet is framed by the bytes DE AD BE EF and carries a checksum; the read request used in testing is 37 bytes. The parser accepts six packet types: read, a three-stage configuration sequence, reboot and failure.

The October 28 bench capture shows a result that looks like a failure and is not. The status block printed _validPacket as false even though the packet was parsed correctly, because the receive loop clears that flag as soon as the reply is sent, before the status block prints. The fields that matter, header state, a 22-byte body, sensor ID 1 and the checksum, showed a good parse. The capture is on the ARC page.

One design choice sits next to this: a sensor with no valid reading is reported as 0xFFFF rather than its last value, so the Brain cannot mistake stale data for a current reading.

Scope: isolated bench test, earlier read-only version.

Part of the ARC case study. Described at the CPPDev branch, commit 49d54a0.
